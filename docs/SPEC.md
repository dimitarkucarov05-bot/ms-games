## 1. Координати

Пространство на залата (арена), метри, дясна система като three.js:

- начало: центърът на залата, на пода; **Y нагоре**;
- **+X** по дългата стена; **+Z** към „предната" страна (на плана на пулта: надолу);
- залата е `hall = { w, d }`: x ∈ [−w/2, w/2], z ∈ [−d/2, d/2]. По подразбиране 6 × 6. Поддържа се 4 до 10 м по всяка страна.
- yaw: радиани около Y; yaw = 0 гледа към +Z; посоката е `(sin yaw, cos yaw)` по `(x, z)`.

Поза на играч: 21 числа `p = [глава x,y,z, qx,qy,qz,qw, лява ръка 7, дясна ръка 7]`, в координатите на залата.

## 2. Как е разделена залата

```
z = −d/2  ┌───────────────────────────┐
          │      ЛАБОРАТОРИЯ           │  z < 0
z = 0     ├─────────┤ врата ├─────────┤  стена с отвор 1,2 м в средата (x ∈ [−0.6, 0.6])
          │      МАГАЗИН               │  z > 0
z = +d/2  └────── тезгях ─────────────┘  клиентите стоят отвън, z > d/2 (само виртуално)
```

- Работна височина на всички плотове: `SURFACE_Y = 0.85`.
- Тезгях: по цялата предна стена, z ∈ [d/2 − 0.5, d/2].
- Станциите са до стените, никога в средата (хората ходят там).
- Досег: ръката трябва да е на до `REACH = 0.45` м от предмета или гнездото.

## 4. Сървър → каска

### `gameStart` (веднъж при старт и при свързване по средата)

```js
{ type: 'gameStart', game: 'backroom', theme: 'night' | 'kids',
  hall: { w, d },
  stations: [ { id, kind, x, y, z, yaw, w, h, d, gives?,           // статичното
                slots: [ { id, x, y, z, accepts: [kind, …] } ] } ], // гнездата са в координати на залата
  seats: [ { i, x, z } ],            // места на клиентите пред тезгяха (z > d/2)
  duration: { tutorial, day, closing, night, rush, raid } }        // секунди
```

### `game` (10 пъти в секунда)

```js
{ type: 'game', t,                          // ms на сървъра
  phase: 'tutorial' | 'day' | 'closing' | 'night' | 'rush' | 'raid' | 'over',
  left,                                     // секунди до края на фазата
  money, cover, suspicion,                  // cover и suspicion: 0 … 1
  hint,                                     // кратък текст за таблото („Обслужете клиентите")
  stations: [ { id, state } ],              // само станциите със състояние, което се мени
  slots: { [slotId]: itemId | null },       // кое гнездо какво държи
  items: [ { id, kind, x, y, z, yaw, holder, hand, slot, state } ],
      // holder: id на играча или null; hand: 'l' | 'r' | null; slot: id на гнездо или null
      // предмет в ръка: x,y,z не важат, рисува се в ръката на holder
  customers: [ { id, look, seat, x, z, yaw, state: 'in' | 'wait' | 'happy' | 'angry' | 'out',
                 patience,                  // 1 … 0
                 order: { kind: 'burger', stack: [kind, …] } | { kind: 'fries' } | { kind: 'cup', drink } | { kind: 'bag' },
                 special } ],
  players: [ { id, n, name, served, cooked, packed, mistakes, hidden } ],   // hidden: скрит ли е при патрул
  patrol: null | { left, phase: 'warn' | 'on' },     // патрулът: 'warn' 3 с преди, 'on' докато минава
  events: [ { id, kind, x?, y?, z?, player?, amount?, text? } ],   // последните 3 с; клиентът ги показва веднъж по id
  result: null | { money, stars, caught, players: [ … ] } }        // само при phase 'over'
```

`events.kind`: `cash` (пари, `amount`), `order_ok`, `order_bad`, `burn`, `ruin`, `mix_ok`, `mix_bad`, `hit`, `miss`, `pack`, `sold`, `phase`, `patrol_warn`, `patrol_on`, `patrol_off`, `caught`, `poof` (предмет изчезна), `deny` (действието е отказано; `text` защо).

## 5. Каска → сървър

Позите вървят отделно (`{ type: 'pose', c, p }`, вече ги има). Действията:

```js
{ type: 'act', a: 'grab',    hand: 'l' | 'r', item }              // хвани предмет
{ type: 'act', a: 'take',    hand, station }                      // вземи нов предмет от bin
{ type: 'act', a: 'release', hand, p: [x, y, z], yaw }            // пусни това, което държи ръката
{ type: 'act', a: 'use',     hand, station, control }             // натисни бутона на станция (control по желание)
```

Сървърът проверява досега по позата на ръката (не вярва на клиента) и връща `deny` събитие при отказ.

Правила за `release` (по ред):

1. Ако до 0.30 м има свободно гнездо, което приема този kind: предметът влиза в гнездото.
2. Ако до 0.25 м има `plate` (в гнездо или на плот) и предметът е част за бургер (`bun_bottom`, `patty`, `cheese`, `lettuce`, `bun_top`): влиза в `stack` на чинията и изчезва като отделен предмет.
3. Ако до 0.25 м има `beaker` и предметът е `ing_*`: влиза в `mix`.
4. Ако е над плот на станция (в правоъгълника ѝ, y до 0.4 над плота): ляга на плота.
5. Иначе пада на пода и след 3 с изчезва (`poof`).

## 6. Правилата на играта (сървърът)

Фази и времена по подразбиране (секунди): `tutorial` 60, `day` 210, `closing` 20, `night` 210, `rush` 180, `raid` 45. Общо около 12 минути. `over` след `raid`.
С `opts.fast = true` всички времена са делени на 6 (за проби).

- **tutorial:** един клиент на играч, без търпение (не си тръгва), поръчка: прост бургер (`bun_bottom, patty, bun_top`). Лабораторията е затворена.
- **day:** клиенти идват на местата (seat) през 6 до 10 с, зависи от броя играчи. Поръчки: бургер (3 до 5 части), `fries`, `cup`. Търпение 45 с. Вярна поръчка: пари (бургер 8 + 2 на част, картофи 5, напитка 4) и бакшиш по търпението. Грешна или изпусната: `mistakes` + по-малко `cover`.
- **closing:** `shutter` се затваря, `door` се отваря, клиентите си тръгват.
- **night:** лабораторията работи.
  1. `mixer.state.recipe` показва 3 до 4 съставки в ред. Слагат се в `beaker` (в гнездото на mixer) в същия ред. `use` на mixer: вярно → `mixed: true` (`mix_ok`); грешно → колбата се изпразва (`mix_bad`).
  2. Колбата отива на `burner`. Иглата `needle` се люлее 0 … 1. `use`, докато е в `zone` → `hits + 1` (`hit`); извън → `miss` и `suspicion + 0.05`. При 3 удара: колбата изчезва, на плота на burner се появява `tray` с `ready: true`.
  3. `tray` отива на `packer`. Всяко `use` вдига `progress` с 0.25; на 1 се раждат 4 `bag` на плота.
  4. `bag` в `hatch` → пари (25 на пакет).
  - **Патрул:** на 50 до 80 с. 3 с предупреждение (`patrol.phase = 'warn'`), после 6 с `'on'`. Докато е `'on'`, всеки играч трябва да е „скрит": главата под 1.15 м (клекнал) **или** да не е мръднал главата с повече от 0.15 м. Който не е: `suspicion + 0.12` и събитие `caught` за него.
- **rush:** магазинът и лабораторията работят заедно. Идват и специални клиенти (`special`, поръчка `bag`). Ако `door.open > 0.5` (някой е в отвора на вратата, |x| < 0.6 и |z| < 0.4), докато обикновен клиент чака: `suspicion` расте.
- **raid:** 45 с. Всичко от лабораторията (ing_*, beaker, tray, bag), което не е в `trash` или продадено, е улика. Накрая: всяка улика −15 пари и `suspicion + 0.05`.
- **over:** `stars` 1 до 5 по парите на играч и по `suspicion`. `caught: suspicion >= 1`.

`suspicion` стига 1 → играта свършва веднага с `caught: true`.

Темата (`night` / `kids`) не сменя правилата. Сменя само текстовете (`hint`, `sign.text`) и как изглеждат моделите.

## 8. Модулът с правилата: `lobby/game/backroom.js`

```js
export function createGame(opts)   // opts: { hall: {w, d}, theme: 'night'|'kids', fast: bool, seed: number, now: ms }
// връща:
game.start()                       // обект за съобщението gameStart (без полето type)
game.join(id, { n, name })         // играч влиза (може и по средата)
game.leave(id)                     // играч излиза: това, което държи, пада
game.pose(id, p)                   // последната поза (21 числа)
game.act(id, msg)                  // действие от т. 5
game.tick(now)                     // върти времето; викa се на всеки 100 ms
game.snapshot()                    // обект за съобщението game (без полето type)
game.over                          // true след края
```

- Чист модул: без мрежа, без файлове, без таймери. Времето идва само от `now`.
- Случайността е от собствен генератор със `seed` (тестовете са повторяеми).
- Тестове с `node --test`: поне цял ден (поръчка → вярно обслужване → пари), цялата верига на лабораторията, патрулът (скрит / хванат), правилата за `release`, отказ при липса на досег, `fast` режим до `over`.

## 10. Сцената: `scene.js`

```js
export async function createScene(ctx, start)    // start е съобщението gameStart
// връща { onSnapshot(snap), update(dt, t), dispose() }
```

`ctx` идва от основата:

```js
ctx = {
  THREE,
  root,                 // THREE.Group в координатите на залата: всичко се добавя тук
  hall: { w, d },
  me: { id, n, name },
  head:  { pos: Vector3, quat: Quaternion },                    // в координати на залата, обновени преди update
  hands: { l: { pos, quat, grip, trigger, active }, r: { … } }, // grip/trigger: bool в момента
  players,              // Map(id → { n, name, team, head:{pos,quat}, l:{pos,quat}, r:{pos,quat} }), другите играчи, вече изгладени
  onInput(fn),          // fn({ type: 'gripdown'|'gripup'|'triggerdown'|'triggerup', hand: 'l'|'r' }); връща функция за отписване
  send(msg),            // праща действие: ctx.send({ a: 'grab', hand: 'r', item: 7 }) (type: 'act' се добавя само)
  haptic(hand, strength, ms),
  desktop,              // true в режим без каска
  theme,
}
```

Основата рисува аватарите на играчите (глава, ръце, номер) и собствените ръце. Сцената рисува всичко друго.

Какво прави сцената:

- От `start`: строи станциите, стената, тезгяха, местата. От `onSnapshot`: създава, мести и маха предмети и клиенти; обновява състоянията с `setModelState`.
- Предмет с `holder`: рисува се в ръката на този играч (за `ctx.me.id` от `ctx.hands`, за другите от `ctx.players`). Свободните предмети се движат плавно към новото си място.
- **Хващане:** при `gripdown` (или `triggerdown`) на ръка без предмет: най-близкият свободен предмет до 0.25 м → `grab`; ако няма, най-близкият `bin` до 0.45 м → `take`; ако няма, най-близката станция с бутон до 0.45 м → `use`. При `gripup` на ръка с предмет → `release` с позицията на ръката.
- Подсветка: предметът или гнездото, което ще се хване/приеме, се оцветява леко. Кратка вибрация при хващане и при `deny`.
- Поръчката на клиент се вижда над главата му като малки модели (не текст) + лента за търпението.
- **`hud.js`:** табло на стената (не залепено за лицето): фаза, време, пари, `hint`, две ленти (`cover`, `suspicion`). Текст през `CanvasTexture`. При `patrol`: стаята притъмнява и минава синя светлина. При `over`: голямо табло с резултата.
- **`mock.js`:** фалшив сървър в браузъра, който дава `gameStart` и `game` по тази спецификация (няколко предмета, клиент, сменящи се фази), за да се пробва сцената без истинския.
- **`scene-preview.html`:** пуска сцената с `mock.js` и камера с мишка и клавиши, без каска.

   Вече готовите се прескачат. Може да се пуска едновременно от няколко сесии (има заключване по пакет).

## 12. Две нива и асансьорът (добавено 12.11.2026, 21:40, по искане на собственика)

Същата истинска зала се ползва за **две виртуални нива**. Така мястото се удвоява и лабораторията е скрита под земята.

| `level` | Какво е | Как изглежда |
|---|---|---|
| `0` | Улично ниво: щандът (z > 0) и зад него **склад** (z < 0) | Щандът е отворен към града. Складът е обикновен заден склад: стелажи, кашони, палети. Между тях е хладилната врата (както досега). |
| `1` | **Подземната лаборатория**: цялата зала | Скъпа, „мафиотска" лаборатория: UV и лилави лампи, саксии и растения, които растат, лабораторни маси, ъгъл на шефа с бюро и компютър. |

**Асансьорът** е тайният път между нивата. Стои в заден ъгъл на склада, опрян в две стени, на едно и също истинско място на двете нива.

- Нов вид станция `elevator`: кабина 1.6 × 2.3 × 1.6 м (ш × в × д), без гнезда. Състояние `{ doors: 0…1 (1 = отворени), moving: bool, level: 0|1 (къде е кабината), riders: [id на играчи вътре] }`.
- `gameStart` носи `elevator: { x, z, w: 1.6, d: 1.6 }` (центърът и размерът на пода на кабината) и `levels: 2`.
- Всеки играч има `level` (в `players[]` на `game`). Започва на 0.
- **Возене:** играч, чиято глава е над пода на кабината, натиска бутона (`use` на станцията `elevator`). Вратите се затварят (1 с), кабината „пътува" 3 с, вратите се отварят на другото ниво. Всички, които са вътре в този миг, сменят `level`. Събития: `ride_start { to }`, `ride_end { to }`. Докато пътува, бутонът не прави нищо.
- **Всяка станция, гнездо и свободен предмет има `level`.** Предмет в ръка пътува с играча. Действията стигат само неща на нивото на играча.
- Кое къде е: на ниво 0, отпред, всичко от магазина; на ниво 0, в склада, кашоните със съставките за лабораторията (`bin` за `ing_*` и `beaker`) и `trash`; на ниво 1: `mixer`, `burner`, `packer`, `grow`, `hatch`, табло с рецептата. Така съставките се свалят долу, а пакетчетата се качват горе при специалните клиенти.
- Патрулът гледа само играчите на ниво 0. Долу си в безопасност, но ако кабината пътува по време на патрул, подозрението расте.
- Фазите не се менят: `night` = магазинът е затворен, работи се долу; `rush` = двете нива наведнъж.

**Клиентът (сцена и обстановка):** рисува само нивото на местния играч (`players[me].level`). Играчите на другото ниво се рисуват от основата като бледи силуети, защото са в същата истинска стая и може да се блъснат. При возене: вратите се затварят, кабината трепери, светът отвън се сменя, вратите се отварят. Обстановката строи двете нива и показва едното; смяната не бива да зарежда нищо в момента на возенето.

## 13. Стаи: играта ползва цялата начертана зона (добавено 12.11.2026, 21:55)

Истинската зала на собственика е малка и крива (около 5 × 2,5 м с ръкав). Един правоъгълник хваща по-малко от половината.
Затова зоната се разделя на **до три стаи**: правоъгълници, успоредни на осите на залата, които не се застъпват и се допират със стена.
Това заменя единичната `hall` навсякъде, където се подрежда нещо.

```js
rooms: [ { id: 'a', x, z, w, d }, { id: 'b', x, z, w, d } ]   // център и размер, в координатите на залата
doors: [ { a: 'a', b: 'b', x, z, w, axis: 'x' | 'z' } ]         // отвор в общата стена: център, ширина (≥ 0.8 м), по коя ос върви стената
```

- Стая `a` е най-голямата и началото на координатите е нейният център. `hall = { w, d }` остава размерът на стая `a`, за да не се чупи старият код.
- Стаите идват от сървъра: `createGame(opts)` получава `opts.rooms` и `opts.doors` (ако липсват: една стая с размера на `opts.hall`), а `start()` ги връща като `rooms` и `doors`. Всяка станция носи `room` (id на стаята си).
- **Нищо никога не е извън стаите.** Стаите са с истинските размери, без закръгляне нагоре. Най-малката допълнителна стая е ниша 1,0 × 1,5 м (става за рафтове и кашони, не за асансьор). Най-малката стая `a`: 2,4 × 1,6 м. Асансьорът иска 1,6 × 1,6 м: ако няма стая с толкова място извън пътеката, кабината се смалява до 1,2 × 1,2 м.
- Отворът между стаите остава свободен на 0,5 м от двете страни.

Как се разпределят (заедно с нивата от т. 12):

| | Една стая | Две или три стаи |
|---|---|---|
| Ниво 0 | Щандът; асансьорът е в ъгъл на щанда, маскиран като хладилна камера. | Стая `a` е щандът, тезгяхът е на външна стена срещу или встрани от отвора. Стая `b` е складът с асансьора; хладилната врата е в отвора. Трета стая: още склад. |
| Ниво 1 | Цялата стая е лабораторията. | Лабораторията е във всички стаи: станциите по всички външни стени, отворите са свободни. В по-малката стая са растенията и ъгълът на шефа. |

Когато стените не стигат: кашоните със съставки стават рафтове на два-три етажа една над друга (гнезда на 0,85, 1,25 и 1,6 м), станциите се стесняват до нужното, скарата остава с едно-две места, местата на тезгяха колкото се поберат (поне едно). В средата на всяка стая остава свободна пътека, широка поне 1 м.
